IIC、I2C 和 I²C 指同一种通信总线。I²C 使用时钟线 SCL 和双向数据线 SDA，在同一总线上通过设备地址选择通信对象，常用于连接 EEPROM、传感器等芯片。

I²C 支持多主多从，也常用于单主多从系统。本次实验只有 STM32 一个主机，目标从机是开发板上的 24C02 EEPROM。

本文记录 2026 年 11 月 20 日的软件 I²C、硬件 I²C 学习内容。开发板为正点原子探索者 STM32F407 V3，芯片为 STM32F407ZGT6，工程使用 STM32CubeMX、VS Code 和 HAL 库。

## 两根线与开漏输出

| 信号 | 本次引脚 | 作用 |
| --- | --- | --- |
| SCL | PB8 | 主机产生通信时钟 |
| SDA | PB9 | 双向传输地址、数据和应答 |

按本次开发板的连接，板载 EEPROM 已经连接这两根线，无需额外跳线。两根线各有 4.7 kΩ 电阻上拉到 3.3 V，本次不使用 GPIO 内部上拉。

开漏输出的两个动作：

```c
HAL_GPIO_WritePin(port, pin, GPIO_PIN_RESET); // 主动拉低线路
HAL_GPIO_WritePin(port, pin, GPIO_PIN_SET);   // 释放线路，由电阻上拉
```

**开漏写 1 表示释放，不是主动输出高电平。** 释放 SDA 后，从机仍然可以将线路拉低，主机通过 `HAL_GPIO_ReadPin()` 读取实际电平。这使数据发送方和接收方能够轮流控制 SDA。

SCL 采用开漏还允许从机通过保持 SCL 为低来延长等待时间，即时钟拉伸。本次软件示例按 EEPROM 正常响应、不发生时钟拉伸的条件编写，没有实现拉伸等待和多主仲裁。

之前完成的 GPIO 实验结果：主动拉低 SDA 读到 0，释放 SDA 读到 1，释放 SCL 读到 1。

## 起始、停止和数据位

| 动作 | SCL 状态 | SDA 动作 |
| --- | --- | --- |
| 起始 START | 高电平 | 从高变低 |
| 停止 STOP | 高电平 | 从低变高 |
| 准备普通数据位 | 低电平 | 设置为这一位对应的电平 |
| 读取普通数据位 | 高电平 | 保持稳定，让接收方读取 |

**低电平期间准备数据，高电平期间保持数据稳定。** START 和 STOP 是 SDA 在 SCL 高电平期间变化的特殊情况。

一次传输中的数据字节按最高位先发送：bit7、bit6，直到 bit0。

## ACK 与 NACK

每传输 8 位后，主机还要产生第 9 个时钟，用于传输应答位。

- ACK：接收方在第 9 个时钟将 SDA 拉低，表示应答。
- NACK：第 9 个时钟 SDA 保持高电平，表示未应答或不再继续接收。

**前 8 位由发送方控制 SDA；第 9 位由接收方决定应答。第 9 个时钟仍由主机产生。** 发送方必须先释放 SDA，接收方才能正确应答。

单字节读取结束时，STM32 发送 NACK，告诉 EEPROM 不再继续读，再发送 STOP。这是正常的结束操作。

注意：普通数据位的低电平表示 0，而 ACK 的低电平表示应答成功，不能把两个判断混在一起。自定义函数可以用 1 表示“收到 ACK”，但 HAL 的 `HAL_OK` 数值为 0。

## 设备地址、内部地址和数据

本次板载 24C02 的 A2、A1、A0 接地，7 位设备地址为 `0x50`。它共有 256 字节，内部存储地址为 `0x00～0xFF`。

设备地址后面加一位方向，形成线路上的第一个字节：

```text
7 位设备地址：1010000 = 0x50

写方向：1010000 0 = 0xA0
读方向：1010000 1 = 0xA1
```

```c
(0x50U << 1) | 0U  // 写方向
(0x50U << 1) | 1U  // 读方向
```

| 示例 | 含义 |
| --- | --- |
| 设备地址 `0x50` | 选择总线上的哪颗芯片 |
| 内部地址 `0x00` | 选择这颗芯片内部的哪个存储单元 |
| 数据 `0x5A` | 要保存的一个字节内容 |

## EEPROM 单字节写入与读取

### 写入一个字节

调用 `EEPROM_WriteByte(0x00, 0x5A)` 时，目标是把数据 `0x5A` 保存到 EEPROM 内部地址 `0x00`。

```text
START
  → STM32 发送 0xA0 → EEPROM 回复 ACK
  → STM32 发送0x00 → EEPROM 回复ACK
  → STM32 发送0x5A → EEPROM 回复ACK
  → STOP
  → 等待内部写入完成
```

STOP 后 EEPROM 还需要内部写入时间。本次代码等待 10 ms，再执行后续操作；实际等待时间应覆盖所用器件数据手册规定的最大写周期，也可通过 ACK 轮询确认写入完成。总线上的数据发送完成，不等于 EEPROM 已经完成内部保存。

### 指定地址读取一个字节

调用 `EEPROM_ReadByte(0x00, &eeprom_data)`，将指定位置的内容保存到变量 `eeprom_data`。

```text
START
  → STM32 发送0xA0 → EEPROM 回复ACK
  → STM32 发送0x00 → EEPROM 回复ACK
  → 重复 START
  → STM32 发送0xA1 → EEPROM 回复ACK
  → EEPROM 输出8 位数据，STM32 接收
  → STM32 发送 NACK
  → STOP
```

读取前先用写方向发送内部地址，是为了告诉 EEPROM 接下来从哪里读取。这一阶段只发送地址，没有发送待保存的数据。重复 START 在不释放总线的情况下，重新发送设备地址并切换为读方向。

## I²C 通信流程的整体理解

### 主机怎样发起通信

I²C 支持多主多从，但不能靠“谁先拉低 SCL”来确定主机。主机先确认总线空闲，再发送 START，开始一次通信。

通信过程中，两根线暂时同时为高，也不代表传输已经结束，需要结合 START、STOP 判断总线状态。

如果两个主机几乎同时开始，需要通过时钟同步和仲裁决定谁继续。主机发送时也观察 SDA，**如果自己想发送 1，却读到 0，就知道自己失去仲裁，需要退出竞争。** 本次 STM32 是唯一主机，EEPROM 是从机，软件驱动未实现多主仲裁。

### 先发送从机地址，再由从机回复 ACK

原来的理解是“主机先给目标从机发送 ACK，再发送数据”，应修正为：

```text
主机发送 START
    ↓
主机发送“从机地址＋读写方向”
    ↓
被选中的从机回复 ACK
    ↓
开始传输后续内容
```

**从机通过地址知道“这次是在找我”，ACK 是它收到后的应答。** ACK 本身不包含目标地址，也不是主机用来选择从机的命令。

结合前面的 EEPROM 写入流程：STM32 先发送 0xA0 选择设备，再发送 0x00 指定内部位置，最后发送 0x5A作为数据；EEPROM 在每个字节之后分别回复 ACK，最后由 STM32 发送 STOP。

### 发送时，在 SCL 低电平期间准备 SDA

原来的理解是“在 SCL 高电平时把数据放到 SDA 上”，应修正为：

```text
STM32 拉低 SCL
    ↓
STM32 设置 SDA，准备这一位数据
    ↓
STM32 释放 SCL，使其升高；SDA 保持不变，EEPROM 读取
    ↓
STM32 拉低 SCL，准备下一位
```

对应发送一位的代码如下，放在软件发送函数的循环内：

```c
I2C_SCL(0);

I2C_SDA((data & 0x80U) != 0U);
I2C_Delay();

I2C_SCL(1);
I2C_Delay();

I2C_SCL(0);
I2C_Delay();

data <<= 1;
```

**普通数据传输期间：低电平时准备或改变 SDA，高电平时保持 SDA 稳定。** 如果在 SCL 高电平期间改变 SDA，就可能被对方识别为 START 或 STOP。

### 接收时，SDA 的控制方改变，时钟仍由主机产生

“接收时反过来”指 EEPROM 输出数据、STM32 读取数据。它不表示时钟改由 EEPROM 产生，也不表示数据电平与位值反过来。

```text
STM32 释放 SDA，让 EEPROM 控制数据线
    ↓
SCL 低电平期间，EEPROM 准备数据
    ↓
STM32 释放 SCL，使其升高，并读取 SDA
    ↓
STM32 拉低 SCL，进入下一位
```

| 阶段 | 谁控制 SDA | STM32 在做什么 |
| --- | --- | --- |
| STM32 发送 8 位地址或数据 | STM32 | 设置数据、产生时钟 |
| EEPROM 回复 ACK | EEPROM | 释放 SDA、产生第 9 个时钟并读取应答 |
| EEPROM 发送 8 位数据 | EEPROM | 释放 SDA、产生时钟并读取数据 |
| STM32 结束单字节读取 | STM32 | 第 9 个时钟保持 SDA 释放为高，发送 NACK |

> 主机在总线空闲后发送 START，再发送地址和读写方向，由从机回复 ACK。传输每一位时，发送方在 SCL 低电平期间准备数据，接收方在高电平期间读取。读写过程中，时钟都由主机产生。

## 软件 I²C 实现要点

软件 I²C 使用普通 GPIO，由程序逐次控制两根线。

CubeMX 中关闭 I2C1，将 PB8、PB9 配置为普通开漏输出、无内部上下拉。可以将初始输出设为 High、输出速度设为 Low；初始化完成后释放两根线。GPIO 的输出速度设置控制引脚边沿特性，不直接决定通信时钟频率。

软件控制要求普通 GPIO 输出模式。之前误用 `GPIO_MODE_AF_OD` 时，引脚由外设复用功能控制，普通 GPIO 写操作无法按预期拉低 SDA；切换为 `GPIO_MODE_OUTPUT_OD` 后电平实验通过。

### 文件组织

```text
Core/Inc/eeprom.h：引脚定义和对外接口声明
Core/Src/eeprom.c：起始、停止、逐位收发和 EEPROM 操作实现
Core/Src/main.c：初始化、调用接口、打印结果
```

头文件中集中定义引脚，修改时同时调整 CubeMX GPIO 配置和实际接线。板载 EEPROM 已固定连接 PB8、PB9，不能仅改宏就改变板上走线。

```c
#ifndef EEPROM_H
#define EEPROM_H

#include "stm32f4xx_hal.h"

#define EEPROM_SCL_GPIO_PORT GPIOB
#define EEPROM_SCL_GPIO_PIN  GPIO_PIN_8
#define EEPROM_SDA_GPIO_PORT GPIOB
#define EEPROM_SDA_GPIO_PIN  GPIO_PIN_9

/* 软件接口统一保存7 位地址，由发送代码补读写位 */
#define EEPROM_DEVICE_ADDRESS 0x50U

void EEPROM_Init(void);
HAL_StatusTypeDef EEPROM_Check(void);
HAL_StatusTypeDef EEPROM_WriteByte(uint8_t address, uint8_t data);
HAL_StatusTypeDef EEPROM_ReadByte(uint8_t address, uint8_t *data);

#endif
```

`eeprom.c` 中包含 `eeprom.h`，`main.c` 也通过包含头文件使用接口，不直接包含 `.c` 文件。带 `static` 的辅助函数仅在 `eeprom.c` 内部使用。

工程根目录 `CMakeLists.txt` 中把源文件加入现有列表：

```cmake
target_sources(${CMAKE_PROJECT_NAME} PRIVATE
    Core/Src/eeprom.c
)
```

### 发送 8 位与检查 ACK

以下是函数内部的时序片段，并非完整驱动；`status` 为发送函数中声明的 `HAL_StatusTypeDef` 变量。片段放在 `eeprom.c` 中对应的函数内部。`I2C_SCL(0)`、`I2C_SDA(0)` 表示拉低；参数为 1 表示释放；`I2C_Delay()` 为通信延时辅助函数。

```c
/* 发送函数内部：先发送当前最高位 */
for (uint8_t i = 0; i < 8; i++)
{
    I2C_SCL(0);
    I2C_SDA((data & 0x80U) != 0U);
    I2C_Delay();

    I2C_SCL(1);
    I2C_Delay();

    I2C_SCL(0);
    I2C_Delay();

    data <<= 1;
}

/* 发完8 位，必须释放 SDA */
I2C_SDA(1);
I2C_Delay();

I2C_SCL(1);
I2C_Delay();

if (HAL_GPIO_ReadPin(EEPROM_SDA_GPIO_PORT,
                     EEPROM_SDA_GPIO_PIN) == GPIO_PIN_RESET)
{
    status = HAL_OK;  // 第9 个时钟读到低电平：收到 ACK
}
else
{
    status = HAL_ERROR;
}

I2C_SCL(0);
I2C_Delay();
```

`data & 0x80U` 检查最高位，`data <<= 1` 把下一位移到最高位，等待下一轮发送。

### 接收 8 位与组装数据

```c
/* 接收函数内部：先确保 SCL 为低，再释放 SDA */
uint8_t data = 0;
I2C_SCL(0);
I2C_SDA(1);  // 释放 SDA，让 EEPROM 输出数据

for (uint8_t i = 0; i < 8; i++)
{
    I2C_Delay();
    I2C_SCL(1);
    I2C_Delay();

    data <<= 1;
    if (HAL_GPIO_ReadPin(EEPROM_SDA_GPIO_PORT,
                         EEPROM_SDA_GPIO_PIN) == GPIO_PIN_SET)
    {
        data |= 1U;
    }

    I2C_SCL(0);
    I2C_Delay();
}

/* 只读一个字节：第9 个时钟发送 NACK */
I2C_SDA(1);
I2C_Delay();
I2C_SCL(1);
I2C_Delay();
I2C_SCL(0);
I2C_Delay();
```

`data <<= 1` 将已收到的数据左移，最低位空出 0；本次读到高电平，就用 `data |= 1U` 将最低位置 1。低电平则不置位。

本次软件程序使用毫秒延时，适合观察和理解顺序，通信速度较慢；不能将其看作精确的 100 kHz实现。接口在主循环中调用，不放进中断回调。

## 硬件 I²C：I2C1 与 HAL

软件 I²C 逐次调用 GPIO 函数产生时序，硬件 I²C 则由 I2C1 外设产生时序。本次使用 HAL 阻塞接口，CPU 仍在函数中等待完成；使用硬件外设不等于调用过程自动变成异步。

### CubeMX 配置

| 项目 | 本次设置 |
| --- | --- |
| 外设 | I2C1，I2C 模式 |
| SCL / SDA | PB8 / PB9 |
| GPIO 模式 | AF4 复用开漏，无内部上下拉 |
| 时钟速度 | 100000 Hz，即 100 kHz |
| Addressing Mode | 7-bit |
| Duty Cycle | 2，当前标准模式沿用默认值 |
| Own Address1 | 0，本次不作为从机使用 |
| Dual Address / General Call | Disabled |
| No Stretch Mode | Disabled |
| I2C 中断 / DMA | 本次阻塞实验不启用 |

`Own Address` 是 STM32 作为从机时的地址，不是 EEPROM 的设备地址。当前 PCLK1=42 MHz，I2C1 的时序配置基于这个外设时钟，不套用此前 APB1 定时器的 84 MHz时钟。

生成代码后，在 `main.c` 中包含 `i2c.h`，并在初始化阶段调用 `MX_I2C1_Init()`。切换到硬件模式后，不再调用原来通过 GPIO 操作线路的软件 EEPROM 接口。

### 地址宏的统一约定

下面的 HAL 示例使用两个名字明确区分 7 位地址和接口参数：

```c
#define EEPROM_ADDRESS_7BIT  0x50U
#define EEPROM_HAL_ADDRESS  (EEPROM_ADDRESS_7BIT << 1)
```

STM32F4 的这些 HAL 接口要求设备地址左移 1 位后传入，写入和读取都传 `EEPROM_HAL_ADDRESS`，由 HAL 处理方向位。不要在调用前又手动加上读方向位，也不要重复左移。

本次硬件实验工程仍保留旧的 `EEPROM_DEVICE_ADDRESS` 表达式 `(0x50 << 1) | 0`，用于 HAL 时值为 0xA0。后续复用软件驱动前应按上面的命名统一：软件使用 7 位地址再移位，HAL 使用移位后的地址。不要让同一个宏同时承担两种含义；表达式宏应加整体括号。

### 初始化后检测并写入一次

`main.c` 的 `USER CODE BEGIN Includes` 区域包含 `stdio.h`；确保已包含生成的 `i2c.h`。地址宏放在 `USER CODE BEGIN PD`。全局变量放在 `USER CODE BEGIN PV`：

```c
HAL_StatusTypeDef eeprom_status;
uint8_t eeprom_write_data = 0x3C;
uint8_t eeprom_data = 0;
```

以下代码放在 `main()` 的 `USER CODE BEGIN 2` 区域，即 CubeMX 初始化完成后、进入主循环之前。每次启动只写入一次。

```c
eeprom_status = HAL_I2C_IsDeviceReady(
    &hi2c1, EEPROM_HAL_ADDRESS, 3, 100);

printf("EEPROM check status=%u\r\n",
       (unsigned int)eeprom_status);

if (eeprom_status == HAL_OK)
{
    eeprom_status = HAL_I2C_Mem_Write(
        &hi2c1,
        EEPROM_HAL_ADDRESS,
        0x00,
        I2C_MEMADD_SIZE_8BIT,
        &eeprom_write_data,
        1,
        100);

    if (eeprom_status == HAL_OK)
    {
        HAL_Delay(10);
    }

    printf("EEPROM write status=%u\r\n",
           (unsigned int)eeprom_status);
}
```

`HAL_I2C_IsDeviceReady()` 用于检测设备是否应答；这里最多尝试 3 次，超时参数为 100 ms。

### 主循环读回

下面代码放在 `while (1)` 内原有的 `USER CODE BEGIN 3` 区域。保留已有的 `printf()` 串口重定向，不需要新增回调函数。

```c
eeprom_status = HAL_I2C_Mem_Read(
    &hi2c1,
    EEPROM_HAL_ADDRESS,
    0x00,
    I2C_MEMADD_SIZE_8BIT,
    &eeprom_data,
    1,
    100);

if (eeprom_status == HAL_OK)
{
    printf("EEPROM [0x00] = 0x%02X\r\n",
           (unsigned int)eeprom_data);
}
else
{
    printf("Read failed: status=%u, error=0x%lX\r\n",
           (unsigned int)eeprom_status,
           (unsigned long)HAL_I2C_GetError(&hi2c1));
}

HAL_Delay(1000);
```

| Mem_Write / Mem_Read 参数 | 含义 |
| --- | --- |
| `&hi2c1` | 使用哪个 I²C 外设 |
| `EEPROM_HAL_ADDRESS` | 选择哪个设备 |
| `0x00` | 设备内部的哪个位置 |
| `I2C_MEMADD_SIZE_8BIT` | 内部地址发送 1 字节 |
| `&eeprom_write_data` / `&eeprom_data` | 待发送数据或接收结果的变量地址 |
| `1` | 传输 1 字节数据 |
| `100` | HAL 通信等待的超时参数，单位 ms |

`HAL_OK`、`HAL_ERROR`、`HAL_BUSY`、`HAL_TIMEOUT` 分别表示成功、错误、忙和超时。发生错误时，可以结合 `HAL_I2C_GetError()` 查看原因。总线通信返回成功后，仍应读回比较，确认写入结果。

## 内部地址选择 8BIT还是 16BIT

`I2C_MEMADD_SIZE_8BIT` 或 `I2C_MEMADD_SIZE_16BIT` 决定内部地址字段发送几个字节，必须符合从机协议。

| 内部地址参数 | 8BIT 发送内容 | 16BIT 发送内容 |
| --- | --- | --- |
| `0x0012` | `12` | `00 12` |
| `0x1234` | 只发送低字节 `34` | `12 34` |

16BIT 先发高字节，再发低字节。它不改变数据字节宽度，也不改变设备地址的 7 位寻址方式。

24C02 的地址范围为 0x00～0xFF，使用 8BIT。假设向 0x00 写入 0x3C，却误选 16BIT，省略 ACK 后的发送内容是：

```text
正确 8BIT：设备写地址 → 00 → 3C
                         地址  数据

误选16BIT：设备写地址 → 00 → 00 → 3C
HAL 理解：                 高地址 低地址 数据
24C02 理解：               地址  数据1 数据2
```

在器件就绪、写保护未使能且符合时序要求时，24C02 会把后面的两个字节按页写数据解释，向 0x00 写入 0x00，向 0x01 写入 0x3C。即使收到 ACK、HAL 返回成功，也不代表地址格式正确。这个错误配置只作原理讲解，本次没有进行对应上板实验。
