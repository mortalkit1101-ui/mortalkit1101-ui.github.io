# 大模型 LLM 分类与文章发布设计

## 目标

将 PyTorch 二分类文章发布到博客，并在首页侧栏使用 Butterfly 原生分类卡片展示一个可扩展的 `大模型 LLM` 分类。最终以桌面端、移动端和分类页均能正常展示为验收标准。

## 分类规则

- 对外只显示单一分类名 `大模型 LLM`。
- 文章 Front Matter 的 `categories` 中出现 `大模型`、`LLM` 或两者同时出现时，构建时统一归入 `大模型 LLM`。
- 同一篇文章命中多个别名时只计入一次。
- 不匹配这两个别名的其他分类保持原样，方便以后扩展新的文章类别。
- 当前文章的 Front Matter 直接使用规范名称 `大模型 LLM`。

## 分类卡片

- 继续使用已启用的 Butterfly `card_categories`，不创建重复的自定义卡片。
- 首页侧栏显示分类名称与文章数量；点击分类名称进入对应分类页。
- 新分类将由 Hexo 和 Butterfly 根据文章 Front Matter 自动追加到同一卡片。

## 分类页排序

- 每个分类页根据文章 Front Matter 的 `date` 从新到旧排列。
- 不使用文件创建时间或文件修改时间参与排序。
- 发布验证检查每篇文章具有可解析的 `date`，避免分类页顺序不确定。

## 数据流

1. Hexo 读取 Markdown Front Matter。
2. 构建脚本将 `大模型` 和 `LLM` 别名归一化为 `大模型 LLM`。
3. Hexo 生成首页、文章页与分类页。
4. Butterfly 原生分类卡片从 Hexo 分类数据中显示名称和数量。
5. 生成后的静态站点通过仓库现有发布脚本同步到独立的 `main` 分支。

## 验证与发布

- 自动验证分类归一化、分类数量、分类链接和分类页日期降序。
- 运行 Hexo 本地构建并检查生成 HTML。
- 在桌面与移动视口检查首页、分类页和文章页的实际渲染。
- 将 Hexo 源文件提交并推送到 `source` 分支。
- 使用现有安全发布脚本将静态站点正常推送到 `main`，不合并无关历史、不强推。
- 发布后访问 `https://041101.xyz`，确认文章、分类卡片和分类页可正常打开。

## 范围边界

- 不改造 Butterfly 的分类组件样式。
- 不删除或覆盖与本次发布无关的用户文件。
- 不将 Obsidian 的工作区状态文件发布为网站内容。
