# 空博客首页设计

## 背景

Blog 源码保存在 `source` 分支，GitHub Pages 线上内容保存在 `main` 分支。现有 29 篇文章删除后，`hexo-generator-index` 在文章数为 0 时不会生成 `public/index.html`；若直接发布，网站根地址将返回 404。

## 目标

- 即使文章数为 0，也生成可访问的博客首页。
- 沿用 Butterfly 当前首页与侧栏结构。
- 首页文章区域在空状态时显示“暂无文章”。
- 新文章出现后自动恢复正常文章列表，不再显示空状态。
- 公告内容精确设置为“从 0 开始的转码学习”。
- 将源码推送至 `source`，将生成站点发布至 `main`。

## 实现设计

### 空首页路由

在根目录 `scripts` 中增加一个 Hexo 生成器。生成器只在 `locals.posts` 为空时返回根路径 `index.html`，并复用 Butterfly 的 `index` 布局与空的文章集合。存在一篇或更多文章时，生成器不返回路由，由 `hexo-generator-index` 继续负责正常首页和分页。

### 空状态界面

修改 Butterfly 的首页文章列表 mixin：

- `page.posts.data` 为空时，在原文章列表容器内渲染一个空状态卡片。
- 卡片只显示“暂无文章”，不伪造标题、日期、分类或文章链接。
- `page.posts.data` 非空时保持现有文章卡片循环不变。

样式加入现有首页样式文件，复用主题颜色、圆角与阴影变量，确保亮色和深色模式下均可读。

### 公告

把 `_config.butterfly.yml` 的公告正文从“记录从 0 开始的转码学习”调整为用户指定的精确文案“从 0 开始的转码学习”。

## 数据流

1. Hexo 加载 `source/_posts`。
2. 若文章集合为空，自定义生成器创建根首页路由。
3. Butterfly `index` 布局收到空文章集合，渲染“暂无文章”。
4. 若以后新增文章，官方首页生成器创建路由，Butterfly 渲染正常文章列表。

## 失败处理

- 自定义生成器只处理文章数为 0 的情况，避免与官方生成器产生重复路径。
- 发布前必须清理并重新生成 `public`，防止旧文章文件残留。
- 若 `public/index.html` 不存在、包含旧文章内容或未包含空状态与新公告，禁止发布 `main`。

## 验证与发布

- 运行 `npm.cmd run clean` 和 `npm.cmd run generate`，要求成功退出。
- 确认 `public/index.html` 存在。
- 确认首页包含“暂无文章”和“从 0 开始的转码学习”。
- 确认生成目录不包含旧文章标题、旧分类或旧公告。
- 提交源码变更并推送 `source`。
- 使用仓库现有 `tools/publish-blog.js` 将清理后的 `public` 正常提交并推送到 `main`。
- 发布后确认 `main` 已更新；浏览器端如仍显示缓存，可强制刷新。

## 保留范围

不恢复任何旧笔记或课程图片，不创建占位文章，不修改头像、背景、关于页、域名和发布仓库配置。
